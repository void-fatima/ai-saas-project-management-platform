# Production operations contract

The portable deployment is a single Nest API, PostgreSQL 17 and a non-root Nginx static web server. A host TLS edge forwards to the web server's loopback-only port. `/api/*` is proxied to the private API; the browser uses same-origin cookies and no server credentials. Database and application networks are private. The API has a separate outbound network for configured SMTP/AI, and the web server has an edge bridge so Docker can publish its loopback port; Docker does not publish ports for containers attached only to internal networks. Multiple replicas remain unsupported until shared rate limits and realtime delivery are implemented. See [Docker's frontend/internal network topology](https://docs.docker.com/engine/network/).

The API validates configuration before listening. Production requires HTTPS, database credentials and a named database; development mail and test AI are forbidden. SMTP and AI are explicitly opt-in and validate their credentials when enabled. Mail uses certificate-verified TLS, bounded transport timeouts, plain text and disabled transport logging; failures return safe errors. SMTP acceptance is not a guarantee of inbox delivery. Operators must verify actual delivery with their chosen provider before launch.

Liveness `/health` only reports process availability. `/ready` (also `/health/ready`) probes PostgreSQL with a bounded timeout and returns 503 on failure. Disabled AI/mail do not fail readiness. Initial startup still requires PostgreSQL; Compose gates the API on healthy PostgreSQL and successful migrations.

SIGTERM/SIGINT mark the process as stopping, reject new work, stop accepting connections, close SSE streams and drain HTTP work before Nest closes its database resources. A ten-second deadline forces a nonzero exit on stalled work; Compose allows fifteen seconds. Forced shutdown can interrupt in-flight requests; clients must refetch persisted state before retrying mutations. A graceful exit is zero.

JSON logs contain allowlisted event names, validated/generated UUID request IDs, route templates, method, status and duration. Paths with parameter values, query strings, unknown URLs, request bodies, headers, credentials, SMTP responses and AI content are omitted. Safe request IDs are returned in headers/errors. Successful health checks are quiet. Log levels are info/warn/error; health failures and unexpected server failures remain visible. Nginx access logging is disabled to avoid raw URL leakage; edge logging must follow the same policy.

The API retains server-side tenant authorization and strict host-only Secure/HttpOnly/SameSite=Strict session cookies. HTTP configuration adds exact CORS origins, fixed allowed headers, 64 KiB body limits, safe parser errors, security headers and bounded header/body receipt timeouts. `TRUST_PROXY_HOPS=1` is safe only with the supplied private API network and a web proxy that overwrites forwarded client addresses. The trusted host edge must overwrite `X-Real-IP`; arbitrary client `X-Forwarded-For` is discarded. Direct deployments default to zero trusted hops. Rate limits remain in process and reset on restart; endpoint-specific authentication limits remain fixed.

Images use lockfile installs, separate build/runtime stages and non-root execution. API runtime contains production dependencies and compiled code; a separate one-shot migration image retains Prisma CLI tooling. Web assets use a fixed `/api` base, CSP, SPA fallback and no developer panel. No environment files enter build contexts. Node's built-in CA roots are used for TLS. Images use maintained major/minor base tags: operators must rebuild, scan and record image digests for each release; bit-for-bit base image reproducibility is not claimed.

An empty PostgreSQL volume creates a restricted `platform_app` login and default table/sequence grants for the migration owner. The API role cannot create schema objects or bypass audit triggers; the migration administrator is never passed to the API. Initial provisioning is separate from upgrades: changing environment passwords does not rotate existing database roles. Restores preserve triggers and migration history, exclude owner/ACL assignments, and require explicit re-granting for the target environment.

Implementation references: [Nest shutdown lifecycle](https://docs.nestjs.com/fundamentals/lifecycle-events), [pnpm isolated deployment](https://pnpm.io/10.x/cli/deploy), [Nodemailer TLS and timeout options](https://nodemailer.com/smtp).

See the [deployment runbook](../deployment/production.md). Cloud provisioning, automated releases, metrics/tracing vendors, distributed limits, multi-region recovery, automatic SMTP retries and a durable mail outbox remain deferred.
